# 硬件采购需求（TASK 39）

日期：2026-08-25 ｜ 状态：需求定稿，据此比价选型；具体型号另行评审

**方法声明**：本文从已定义的 Adapter 接口与配置反推"系统需要什么"，再谈"买什么"。
顺序不可颠倒——不先挑型号。依据文件：`hardware/arm.py`、`hardware/machines.py`、
`hardware/sts_arm.py`、`config/poses.yaml`、`config/recipes.yaml`、
`docs/ROBOT_PROTOCOL.md`、`docs/SAFETY_INTERLOCK.md`、`projects/coffee_fsm/config.json`。

每项需求按三档给出：**必须满足**（不满足则方案不成立）/ **最好满足**（显著提升可靠性或
体验）/ **不需要**（为此花钱是浪费）。

## 一、机械臂（含夹爪）

系统对臂的全部要求就是 `hardware/arm.py` 的语义动作集 + `config/poses.yaml` 的位姿库
+ `docs/ROBOT_PROTOCOL.md` 的串口协议。逐条反推：

### 1. 自由度数：5 自由度臂 + 1 夹爪（J1~J6 布局）

工位覆盖分析（对应 `poses.yaml` 七个位姿，三个工位 + 倒粉动作）：

| 工位/动作 | 位姿 | 需要的关节能力 |
|---|---|---|
| 待机 | HOME | 任意收敛位 |
| 取杯（台面杯架区） | CUP | 基座旋转 J1 对准 + J2/J3 下探台面高度 |
| 放杯/取成品（冲泡位） | BREWER | J1 转向另一方位，J2/J3 保持下探，**J4 腕俯仰保持杯竖直** |
| 热水位（预留） | WATER | 同 BREWER 能力 |
| 出餐位 | SERVE | J1 转向第三方位，J2/J3 前伸递出 |
| 倒粉 | GROUNDS_PICK / GROUNDS_POUR | **J5 腕旋转**翻转粉杯倾倒（`GROUNDS_POUR` 里 J5=2900） |

结论：三个工位分布在台面同一水平面、重力方向一致，**不需要任意空间姿态**，
因此六轴工业臂是浪费；但倒粉必须翻腕，所以最低 **5 个臂部关节 + 1 个夹爪通道**，
即 `config.json` 的 `joint_ids` J1~J6 布局（J6=夹爪）。4 自由度臂做不了
`pour_grounds`，一票否决。

- **必须满足**：≥5 个旋转关节 + 1 个夹爪驱动通道；基座可旋转 ≥180°（三工位扇形排布）
- **最好满足**：6 轴全旋转（J6 若做成旋转腕而非夹爪也可，但需另有夹爪通道）
- **不需要**：任意姿态可达性、冗余 7 轴

### 2. 负载：额定负载 ≥1kg（安全裕量 ≥2×）

负载账（取整保守值）：

| 项目 | 重量 |
|---|---|
| 空纸杯 | ~10g |
| 满杯饮品（`recipes.yaml` 水量 200~300ml → 200~300g + 杯） | ~250~350g |
| 末端夹爪自重（小舵机夹爪典型值） | ~150~250g |
| **末端合计** | **~400~600g** |

按安全裕量 ≥2×（臂厂额定负载通常指腕部、未计夹爪自重，且舵机臂标称普遍乐观）：
**额定负载 ≥1kg（在最大臂展处）**；最好 1.5kg。倒粉时粉杯（<100g）远低于此限。

- **必须满足**：最大臂展处额定负载 ≥1kg
- **最好满足**：≥1.5kg，留出加料（奶/糖包）动作空间
- **不需要**：>3kg 工业级负载

### 3. 臂展：工作半径 ≥250mm，建议 300~400mm

`poses.yaml` 的 joints 当前全是中位占位值（文件头明确标注"真机使用前必须 teach"），
无法直接反算臂展；从手眼标定配置推：取杯参考点 `cup_ref_x_mm=150, cup_ref_y_mm=90`
（`config.json`），即取杯工位距臂基座约 √（150²+90²)≈175mm。三个工位围绕基座扇形
排布，加上递出余量与冲泡机机身后移，取 **250mm 为下限，300~400mm 舒适区**。
超过 500mm 的臂只会更贵更晃，台面摆不下也没有收益。

- **必须满足**：有效工作半径 ≥250mm（负载 600g 下不打折）
- **最好满足**：300~400mm，工位布局不用抠毫米
- **不需要**：>500mm 大臂展

### 4. 重复定位精度：≤±2mm 为达标线，≤±5mm 可接受（视觉闭环兜底）

精度账：杯口圆检测中杯口半径约 85px（`cup_detect.py` HoughCircles 量程
40~200px 内的典型检出值），12oz 纸杯杯口实际半径约 45mm → 标定平面
**约 0.53mm/px**。`hand_eye_calib.py` 的重投影误差告警线是 5mm，Hough 圆心
定位残差几个像素 → **视觉纠偏残差 ±2mm 级**。
链路设计是"臂粗定位 + 视觉精纠"：`pick_cup(correction_mm=(dx,dy))`
（`arm.py:22`）/ 协议 `PICK_CUP [dx,dy]` int8 mm（ROBOT_PROTOCOL §三 0x04）。
因此：

- 开环盲放（出餐位、冲泡位）：杯身与杯托/出水口的机械容差一般 ≥±10mm，
  臂开环 ±5mm 可接受；
- 取杯走视觉闭环：臂的重复定位精度只决定纠偏量大小，±5mm 内都能被
  ±2mm 级视觉残差兜住；
- **达标线定为 ±2mm**：此时盲放也直接够，视觉纠偏只处理杯摆放误差。

- **必须满足**：重复定位精度 ≤±5mm，且**支持位置回读**（到位校验依赖，
  `sts_arm.py:_goto` 写后必读，超 `position_tolerance` 即报错）
- **最好满足**：≤±2mm；带负载回读/电流回读（协议 OVERCURRENT 0x03 有码可报）
- **不需要**：±0.1mm 工业级精度

### 5. 控制接口：串行总线舵机（TTL 半双工 UART），与现有代码零改动对接

`hardware/sts_arm.py` 与 `config.json` 已把接口锁死为**飞特 STS/SCS 风格总线舵机**：

- 物理层：TTL 半双工串口，115200 8N1，菊链多 ID（J1~J6 = ID 1~6）
- 指令面：位置写（0~4095，12bit）、速度/时间参数、**位置回读**、**扭矩开关**
  （`torque(sid, False)` 是软件急停的实现基础）
- 板端经 USB-TTL 转接板直驱（`serial_port: /dev/ttyUSB0`），上位机代码已就绪

| 方案 | 评估 |
|---|---|
| 串口舵机总线（STS 类） | **选定**。代码已写完并仿真通过；单线菊链布线少；回读/卸力指令现成 |
| CAN 总线关节 | 抗干扰更好，但驱动栈/协议要重写 `sts_arm.py`，成本高一截，本负载等级用不上 |
| 脉冲/PWM 舵机 | 需 6 路 PWM + 独立 MCU，无位置回读（到位校验做不了），违背 SAFETY_INTERLOCK §2"放置确认来自回读"的要求，否决 |

- **必须满足**：STS/SCS 协议兼容（位置写/读、扭矩使能、ID 可设）；支持 115200 波特率
- **最好满足**：电流/温度/电压回读寄存器（健康巡检可用）；磁编码（掉电记忆圈数不重要，
  开机 HOME 即可）
- **不需要**：CAN/EtherCAT/RS485 版本、绝对值多圈

### 6. 速度：单位姿 ≤2s，全程不拖慢出杯节奏

`config.json`：`default_speed=500`、`default_time_ms=1200` —— 单位姿移动按 ~1.2s 设计。
`arm_sequence` 最长 5 步（`recipes.yaml`），臂全程 ≤10s，相对 `brew_sec` 120~200s
不是瓶颈。速度不是采购敏感项，但**必须支持软件调速**（倒粉 `speed: 300` 慢倒、
递杯减速防洒）。

- **必须满足**：速度指令可调（协议字段现成）；低速档平稳不抖
- **最好满足**：加减速规划（舵机内部梯形曲线即可）
- **不需要**：高速度指标

### 7. 夹爪：平行夹爪 + 软垫，夹持力受限

纸杯是薄壁锥筒：**捏重了变形洒液，捏轻了满杯 350g 滑脱**。
`sts_arm.py` 当前是位置式闭合（`gripper_close_pos` 固定位置）→ 必须靠机械/电气手段
限力，不能只靠位置参数碰运气。

- **必须满足**：平行夹爪（两指）或包覆式自适应夹爪；夹持面贴硅胶/泡棉软垫（摩擦 +
  缓冲）；夹爪行程覆盖杯身 φ60~90mm（夹杯上 1/3 处）；**闭合限力**——舵机扭矩限制
  （STS 有 torque limit 概念）或串联弹性结构，保证不捏瘪纸杯
- **最好满足**：夹爪开合回读/电流回读（夹到异物可判，协议 OVERCURRENT 路径）
- **不需要**：电动平行伺服夹爪（力控精密夹爪）、柔性气动夹爪

### 8. 急停能力：软件卸力 + 硬件断动力电双通道

SAFETY_INTERLOCK §5 定死了两层：软件急停（`emergency_stop()` 全关节卸力，已随
`sts_arm.py` 就绪）只是第二道防线，**必须有硬件急停回路**：急停按钮直接切断关节
动力电与电器继电器，不依赖任何软件运行。

- **必须满足**：舵机支持扭矩卸力指令；臂动力电源有独立回路可串急停开关/接触器；
  断动力电后臂不坠落砸杯（自重平衡或减速比自锁，小臂可接受缓降）
- **最好满足**：控制板预留 E-STOP 输入口（固件级急停，第三道）
- **不需要**：安全 PLC、STO 认证回路

## 二、咖啡机 / 磨豆机 / 热水设备

控制方式已定：全部**经由智能插座/点动继电器通断电**（`hardware/machines.py`），
板子与电器之间无任何总线。因此对电器的要求全部围绕"通断电能否正确表达开工/停工"：

`Appliance` 两种模式（`machines.py:33-59`）：

| 模式 | 语义 | 对电器的要求 |
|---|---|---|
| `power` | 通电=开工，运行 `run_sec` 后断电 | **机械锁定开关**：拨到"开"就一直工作，**断电再通电自动继续工作** |
| `press` | 吸合 `press_sec` 秒=按一次键 | 电子轻触按键机：需拆机在按键焊点并接**点动继电器**（干接点） |

保护约束：`MAX_RUN_SEC`（磨豆机 60s / 咖啡机 600s / 热水 120s，`machines.py:40,124,132`），
超时强制断电；断电后 `is_on()` 回读校验（继电器粘连检测）。

- **必须满足**：
  - 优先采购**机械锁定开关型**机器（老式滴滤机、拨杆磨豆机常见）——免拆机，
    一个智能插座搞定；下单前实测"通电即工作、断电再通电继续工作"
  - 单台功率 ≤2000W（插座 10A/2500W 规格内，留裕量）
  - 滴滤机出水口下方台面可固定杯托（放杯位机械容差 ≥±10mm）
- **最好满足**：磨豆机带定量/定时（与 `grind_sec` 10~25s 配方参数对齐更稳）；
  热水设备带自停（沸腾/定量自停，与 120s 上限双保险）
- **不需要**：WiFi/APP 智能机型（反而被云绑定，且与插座控制重复）、
  商用意式机（配方全是滴滤/热水系）、流量计级水量控制（滴滤机自控 + 时间保护足够）

功率与插座规格参考（按常见机型）：磨豆机 150~300W、滴滤机 550~1000W、
即热热水 1500~2000W。三台各配一路插座，单路 10A。

## 三、智能插座 / 点动继电器

`wifi_switch.py` 已实现 tasmota / sonoff_diy / custom 三种驱动，走**局域网 HTTP**。

- **必须满足**：
  - **可局域网 HTTP 本地控制**：可刷 Tasmota（首选，`GET /cm?cmnd=Power%20On/Off`）
    或厂商开放本地 API（Sonoff DIY 模式，`POST :8081/zeroconf/switch`）
  - **状态可回读**（`Power` 查询）——断电回读联锁（SAFETY_INTERLOCK §6）依赖真实
    状态，只信"指令已发出"不可接受
  - 2.4GHz WiFi；与板子同局域网；继电器额定 10A/2500W
  - **禁纯云控**（必须翻墙/厂商云中转才能控制的插座一票否决；涂鸦系需可解出
    local key 走本地，不作为首选）
- **最好满足**：电量统计（健康巡检顺带看功率判断机器真在工作）；
  点动（inching）模式内置（电子按键机免焊专用点动模块时可用）
- **不需要**：HomeKit/Matter/米家生态联动、USB 充电口、屏显

电子按键机器还需 **WiFi 点动继电器模块**（干接点，inching 模式，如 Sonoff RE5V1C 类）：
要求同上（本地 HTTP、回读），干接点耐压 ≥5V 即可（并按键两端）。

## 四、摄像头

`vision/cup_detect.py`：俯视画面中 HoughCircles 找杯口圆 → 圆心像素 →
`hand_eye_calib.py` 单应矩阵换算台面 mm 坐标。`ai_host` 还有人脸/疲劳检测（次优先级）。

- **必须满足**：USB UVC 免驱（板端 OpenCV `cv2.VideoCapture` 直读，已验证）；
  1080p 足够（检测在降采样帧上做，更高分辨率只徒增带宽）；**固定机位刚性安装**
  （俯视取杯区，手眼标定一旦做完机位不可动——支架比摄像头本身更要买结实）；
  手动定焦或焦段固定（自动对焦拉风箱会让标定漂移）
- **最好满足**：带宽动态/抗逆光（台面靠窗场景）；第二路 USB 口余量（AI 店员人脸机位）
- **不需要**：4K、高帧率（30fps 足够）、深度相机/结构光、全局快门

## 五、MCU（可选，独立 MCU 方案时才买）

现状：`sts_arm.py` 已经能从板子经 USB-TTL 直驱总线舵机，**MCU 不是必需品**。
独立 MCU 方案（ROBOT_PROTOCOL v1 的上位机↔MCU 形态）只在要"轨迹规划/限位保护/
急停下沉到实时固件"时才引入（SAFETY_INTERLOCK §3 建议臂控器固件侧也拒绝进冲泡区）。

若走此路线，对 MCU 的要求：

- **必须满足**：≥2 路 UART（一路 115200 接板子跑 ROBOT_PROTOCOL，一路半双工 TTL
  跑舵机总线）；能实现协议全部要素：帧格式/CRC16-CCITT/SEQ 去重/ACK 100ms/
  BUSY 进度/动作超时表/ESTOP 最高优先级（任意时刻打断）；姿态表可存储可 teach 写回
  （角度表只存在 MCU 侧，协议原则 §一）；`mock_robot_serial.py` 是行为规范，
  联调以它为对照
- **最好满足**：硬件看门狗；E-STOP 物理输入脚；开源生态（STM32/ESP32）便于调试
- **不需要**：Linux 级性能、CAN、屏幕

实现成本预估：协议 + 舵机主控 + 姿态/限位状态机约 1~2 周固件工作量；
不走此路线则该项整体不采购。

## 七、暂不需要购买清单（及原因）

| 不买 | 原因 |
|---|---|
| 六轴工业机械臂 | 三工位同平面、重力方向一致，5 自由度全覆盖；工业臂需控制柜/安全围栏，台面摆不下，精度（±0.05mm）远超需求，价格 10× |
| 力控夹爪 / 六维力传感器 | 纸杯夹持用"软垫 + 舵机限流"已够；力控夹爪单价超过整臂预算 |
| 深度相机 / 激光雷达 | 杯定位是 2D 单应问题（Hough 圆 + H 矩阵，已验证）；无避障导航需求 |
| PLC / 安全继电器认证回路 | 电器全是通断电控制，智能插座 + 急停按钮串动力电已满足联锁清单 |
| 专用触摸屏一体机 | 点单屏是普通网页（`coffee_kiosk.html`），任意带浏览器的屏/手机皆可 |
| 电磁流量计 / 计量泵 | 水量由滴滤机自控 + `brew_sec` 时间保护兜底（`recipes.yaml` 设计意图） |
| UPS | 断电只损失一杯饮品；急停/恢复流程已覆盖异常断电场景 |
| 云台/自动对焦摄像头 | 机位固定且标定后不可动，云台是负资产 |
