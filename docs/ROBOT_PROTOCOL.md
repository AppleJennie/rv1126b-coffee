# RV1126B ↔ 机械臂 MCU 通信协议（ROBOT_PROTOCOL v1）

日期：2026-08-24 ｜ 状态：协议定稿，纯模拟自测通过（TASK 19）；真串口/真 MCU 待 TASK 20 之后联调

## 一、设计目标与原则

- **只承载语义动作**：上位机（RV1126B）只说"取杯/放杯/递杯"这类语义命令，
  **关节角度表、轨迹规划、限位保护全部在 MCU 侧**（对应 TASK 20 原则：业务层禁止出现舵机角度/ID）。
  上位机永远不发角度，MCU 永远不向上位机要角度。
- 物理层：UART 115200 8N1（未来真接线时确认），全双工，无硬件流控。
- 风格参考飞特 STS 总线协议（`projects/servo_bus/sts_servo.c`）：固定帧头 + 长度 + 校验，
  但指令面从"舵机寄存器读写"换成"语义动作"。
- 参考实现与自测：`projects/servo_bus/mock_robot_serial.py`（纯标准库，
  `python3 mock_robot_serial.py` 跑全链路自测）。

## 二、帧格式（两个方向共用同一格式）

```
字节偏移   0      1      2     3     4      5 .. 5+LEN-1   5+LEN   6+LEN
        +------+------+-----+-----+-----+================+-------+-------+
        | 0xAA | 0x55 | SEQ | CMD | LEN |    PARAMS      | CRC_H | CRC_L |
        +------+------+-----+-----+-----+================+-------+-------+
```

| 字段 | 字节数 | 说明 |
|---|---|---|
| 帧头 | 2 | 固定 `0xAA 0x55`，用于帧同步/重同步 |
| SEQ | 1 | 序号 0~255 循环。**上位机每发一个新命令 +1；重发保持原 SEQ 不变**；MCU 的所有应答帧回显该命令的 SEQ，供上位机匹配 |
| CMD | 1 | 命令码（上位机→MCU，0x01~0x7F）或应答码（MCU→上位机，0x80~0xFF） |
| LEN | 1 | PARAMS 字节数，0~255 |
| PARAMS | LEN | 参数区，命令/应答各自定义（见下表） |
| CRC16 | 2 | CRC16-CCITT（多项式 0x1021，初值 0xFFFF，不反射，无异或输出，即 CRC-16/CCITT-FALSE），计算范围 **SEQ 起到 PARAMS 末字节**（不含帧头），**高字节先发**（大端） |

- 整帧最短 7 字节（LEN=0），最长 262 字节。
- 接收方任意位置校验失败（帧头错/CRC 错）：丢弃 1 字节重新找帧头，不允许静默错位。
- 校验示例：对 ASCII `"123456789"` 计算结果应为 `0x29B1`（标准检验值）。

## 三、命令集（上位机 → MCU）

| CMD | 名称 | PARAMS | 说明 |
|---|---|---|---|
| 0x01 | PING | 无 | 链路探测；MCU 空闲时立即 ACK+DONE |
| 0x02 | HOME | 无 | 回待机位（同时是"上电初始化/回零"） |
| 0x03 | MOVE_POSE | [pose_id] | 移动到语义位姿。pose_id：0=HOME 1=CUP 2=BREWER 3=WATER 4=SERVE 5=GROUNDS_PICK 6=GROUNDS_POUR（与 `config/poses.yaml` 键对应；角度表只存在 MCU 侧） |
| 0x04 | PICK_CUP | 无 或 [dx, dy] | 取杯（下抓+夹爪闭合）。可选 2 字节 int8 视觉纠偏量（单位 mm，基于杯口圆心，由上位机视觉模块给出） |
| 0x05 | PLACE_CUP | 无 | 放杯到冲泡位并松开夹爪 |
| 0x06 | SERVE | 无 | 递杯到出餐位并松开 |
| 0x07 | STOP | 无 | 平滑停止当前动作（减速停，保持扭矩，不清错误态） |
| 0x08 | ESTOP | 无 | 急停：**立即**停一切动作并卸力，进入急停态。任何时候都必须被优先处理 |
| 0x09 | RESET | 无 | 解除急停态/清除错误，重新允许动作（不自动回零，建议随后发 HOME） |

## 四、应答集（MCU → 上位机）

| CMD | 名称 | PARAMS | 性质 | 说明 |
|---|---|---|---|---|
| 0x81 | ACK | 无 | 中间帧 | 已收到并开始处理命令（100ms 内必须发出） |
| 0x82 | BUSY | [progress] | 中间帧 | 执行中，progress = 0~99 百分比，递增；DONE 前可出现任意多次 |
| 0x83 | DONE | 无 | 终止帧 | 命令成功完成 |
| 0x84 | ERROR | [err_code] | 终止帧 | 命令失败/被拒绝，err_code 见第六节 |
| 0x85 | LIMIT | [axis] | 终止帧 | 触发限位，axis = 关节号 1~6（0 表示未知）；等价于 ERROR(0x04)，单列便于上位机区分处理 |
| 0x86 | ESTOP | 无 | 终止帧 | MCU 处于急停态。是对 ESTOP 命令的确认，也是在执行中动作被急停打断时的终止帧 |

应答规则：
- 每个命令帧的应答序列必为 `ACK → (BUSY)* → DONE | ERROR | LIMIT | ESTOP` 之一。
- PING/RESET/STOP 等即时命令允许 `ACK → DONE` 背靠背发出。
- ESTOP 命令本身回 `ACK → ESTOP`；若急停打断了执行中动作，MCU 先给该动作发 `ESTOP`（回显动作的 SEQ）终止之，再回应 ESTOP 命令本身。

## 五、SEQ、超时与重发

- 上位机全局单调递增 SEQ（mod 256），**重发必须用同一 SEQ**，MCU 侧据此去重/防串包。
- 应答帧回显 SEQ；上位机只接受当前在飞命令的 SEQ，其余丢弃（或转交对应等待者）。
- **ACK 超时 = 100ms**：命令发出后 100ms 内没收到 ACK（或任何匹配 SEQ 的应答帧），重发。
- **重发最多 2 次**（共发 3 帧），且**仅针对 ACK 超时**这一种失败；收到 ACK 之后不再重发。
- 3 帧都无应答 → 上位机判定链路故障，向上层报 `ERROR(0x01) 无应答`。
- **动作总超时**（ACK 之后到 DONE 的看门狗）：按命令给上限，建议 PING 1s、HOME 15s、MOVE_POSE 10s、PICK_CUP/PLACE_CUP/SERVE 15s；超时按链路故障处理并考虑发 ESTOP。
- 任何命令执行中收到 ESTOP，MCU 立即执行，不等当前动作收尾。

## 六、ERROR 码表（err_code）

| 码 | 名称 | 含义 |
|---|---|---|
| 0x01 | NO_RESP | 无应答（上位机侧合成：3 帧超时后报给上层；MCU 不会发这个码） |
| 0x02 | POS_ERR | 位置超差（到位检测失败，关节回读与目标偏差超阈值） |
| 0x03 | OVERCURRENT | 过流（舵机电流超阈值，可能夹到异物） |
| 0x04 | LIMIT | 限位触发（也可由 LIMIT 应答帧表达） |
| 0x05 | ESTOP_ACTIVE | 急停态中，拒绝执行动作命令（需 RESET 解除） |
| 0x06 | BAD_PARAM | 参数非法（如未知 pose_id、LEN 与命令定义不符） |
| 0x07 | NOT_HOMED | 未回零，拒绝执行（上电后需先 HOME） |
| 0x08 | BUSY_CONFLICT | 正忙于另一动作，拒绝新动作命令（STOP/ESTOP/PING 不受限） |

## 七、状态图

每个命令独立走一遍（MCU 侧视角）：

```
            收到命令帧
                │
                ▼
        ┌───────────────┐   参数非法/急停中/忙冲突
        │     ACK       │──────────────┐
        └───────┬───────┘              │
                │ 开始执行              ▼
                ▼                ┌──────────┐
        ┌───────────────┐        │  ERROR   │ (终止)
        │  BUSY (n次)    │        └──────────┘
        │ progress 递增  │
        └───┬───────┬───┘
   完成     │       │ 失败/限位
            ▼       ▼
      ┌──────┐  ┌────────────┐
      │ DONE │  │ ERROR/LIMIT│  (终止)
      └──────┘  └────────────┘

任意时刻收到 ESTOP：
        当前动作立即中止 ──► ESTOP(被打断命令的SEQ)
        进入急停态：此后动作命令一律回 ERROR(0x05)，直到 RESET

MCU 全局状态机：
   ┌────────┐  ESTOP   ┌─────────┐  RESET   ┌────────┐
   │ 正常    │────────►│ 急停态   │────────►│ 正常    │
   └────────┘          └─────────┘          └────────┘
```
