## 六、部署到开发板

### 方式 0：串口直传（当前已验证可用，无需网络）

```bash
board-push ~/rv1126b/projects/hello_world/hello_aarch64 /root/hello_aarch64
board-cmd '/root/hello_aarch64'
# 2026-08-23 实测：507K 文件约 28 秒传完，MD5 自动校验，板端输出 Hello, ATK-DLRV1126B! ✔
```

`board-push` = `tools/bin/serial_push.py`（base64 分行写入 + MD5 校验）；
`board-cmd` = `tools/bin/serial_cmd.py`（串口发命令读输出，默认 1500000 波特率）。

### 联网后更快的方式（三选一，需先给板子配网络）

板子 eth0 接网线（可直插 Mac 的 USB 网卡，两端配同网段静态 IP），
或串口里用 wpa_supplicant 连 WiFi、udhcpc 拿 IP，然后：

```bash
# 1. scp（板子已有 sshd）
scp hello_aarch64 root@<板子IP>:/root/

# 2. adb（需板子 OTG 口连电脑且跑 adbd）
adb push hello_aarch64 /userdata/ && adb shell /userdata/hello_aarch64

# 3. rsync（大文件可断点续传）
rsync -avP hello_aarch64 root@<板子IP>:/root/
```

## 九、踩坑记录与经验（2026-08-23 搭建实测）

### 架构

- 本机是 Apple 芯片虚拟机（aarch64），A 盘 x86_64 安装包**全部用不了**，
  报 `Exec format error`。不要再花时间从 Mac 传那 587M 的工具链 zip。
- 板子和本机同为 aarch64，**本机 gcc 原生编译 = 交叉编译**，产物直接上板跑。
- 编译务必加 `-static`：板子是 Buildroot，glibc 版本和 Ubuntu 不一致，
  动态链接程序上板大概率报 `not found` / 段错误。

### 串口

- 波特率是 **1500000**（官方 PDF 明确写的）。115200 会乱码或完全无输出 —— 踩过。
- Type-C 线要插板子上标 **"UART"** 字样的口，不是电源口。
- 串口完全静默（0 字节，连乱码都没有）= 板子没上电/没启动；
  有乱码 = 波特率不对。用这个能快速区分两种问题。
- 板子要插 **12V 电源适配器**，只靠 USB 供电可能起不来。
- Mac 虚拟机里看不到板子 USB 设备时：VMware 菜单
  `虚拟机 → USB 和蓝牙 → 连接对应设备` 把设备透传进来。
- Linux 下串口权限：用户在 `dialout` 组才能免 sudo 用 /dev/ttyACM0
  （已配好；换机器时执行 `sudo usermod -aG dialout $USER` 并重新登录，
  或临时 `sudo chmod a+rw /dev/ttyACM0`）。

### 网络

- 板子网口默认全部 DOWN。**网线链路要两端都启用才有 link**：
  之前主机侧 carrier=0，原因就是板子 eth0 没 up，不是线坏了。
- 没网也能干活：串口 `board-push` 传 500K 约 28 秒，够日常调试用。

### 硬件注意事项（官方 PDF 摘录）

- **MIPI 摄像头不能带电插拔**，要断电再插；镜头方向不要朝向核心板（会烧摄像头）。
- 出厂已烧好固件并检测过，有屏幕的话出厂 UI 里有相机 App 可测摄像头。
- A 盘的《09、用户手册》2026/04 起迁到线上（语雀），本地只剩
  `在线文档链接.txt`，详细手册去线上看。
